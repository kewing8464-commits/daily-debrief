# Daily Debrief, Insights v1 ("Your recipe for a good day") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the Insights starter with the designed Insights tab (decisions log, "Insights (Part 5)"): a period headline, "Your recipe for a good day" factors with proof pages, trends, highlights and people. Food insights wait for the food tracker.

**Architecture:** One pure module, `lib/recipe.ts`, holds all the math and is fully tested. The `/insights` server page loads the saved days for the period plus the previous period and renders cards. `/insights/factor/[id]` shows one factor's proof. The trend chart is a small client component (an SVG of dots plus a 7-day average line).

**Spec:**
- `docs/superpowers/specs/2026-10-28-app-design-decisions.md` (Insights, Voice)
- `docs/superpowers/specs/2026-10-28-daily-debrief-v2-design.md` section 7, call 3 (factor math)

## Global Constraints
- Patterns need 14+ saved debriefs in total. Under that, show `COPY.stillLearning(n)` with a progress bar, plus the "so far" tiles.
- Each factor is shown only with at least 4 days with it and 4 days without it. Show the top 5, ranked by |difference|. The difference is the average score with the factor minus the average of all days in the period, rounded to 0.1 and shown as "+2.4" / "−2.8".
- Always show the honesty line: "Patterns in your own entries, not proof of cause."
- No judgment words about drinks or weed. Plain numbers ("+2.4 points", "9 of 22 days").
- Periods: Month (calendar month, ‹ › arrows, default), 3 months, Year, All.
- Out of scope: Food insights, PDF download, Today's month-report card.

## Review Focus
1. **A period with fewer than 8 saved days:** no factor can qualify. Show "Not enough days in this period to compare yet" instead of an empty list. Test in Task 1.
2. **A factor every day has (or none has):** never listed, because the without side has under 4 days. Test in Task 1.
3. **Tags and people with different casing** ("Jake" vs "jake"): count as one factor. Test in Task 1.
4. **The previous period has no days:** the change line is left out, never "▲ NaN". Test in Task 1.
5. **A bad factor id or period in the URL:** the factor page shows a plain "This pattern isn't in this period", not a crash. Browser check in Task 3.

### Task 1: `lib/recipe.ts`

**Interfaces:**
- Produces: `type Period = 'month' | '3m' | 'year' | 'all'`.
- Produces: `periodRange(period, today, month?: string): { start: string; end: string; prevStart: string; prevEnd: string; label: string }`.
  - month: the calendar month (default today's), clipped to today; prev is the previous calendar month.
  - 3m: the last 91 days. year: the last 365 days. In both, prev is the same length immediately before.
  - all: `start='2000-01-01'`, no previous period (prevStart = prevEnd = '').
- Produces: `type Factor = { id: string; label: string; family: 'workout' | 'sleep' | 'drinks' | 'weed' | 'meetings' | 'person' | 'tag'; has: (d: SavedDay) => boolean }`.
- Produces: `candidateFactors(days: SavedDay[]): Factor[]`.
  - Fixed factors:
    - `workout` "🏋️ Worked out"
    - `sleep-7.5` "💤 Slept 7.5h or more"
    - `sleep-6` "💤 Slept under 6h" (both only for days with hours; days without hours count as "no")
    - `drinks-3` "🍺 3+ drinks"
    - `drinks-0` "🍺 No drinks"
    - `weed` "🌿 Weed"
    - `meetings-4` "💼 4+ meetings"
  - Plus `person:<lowercase name>` "👤 Time with {Name}" and `tag:<lowercase>` "🏷 {tag}" for each person or tag on 4+ days.
- Produces: `recipe(days): { id; label; diff: number; withAvg: number; withoutAvg: number; withDays: number; withoutDays: number }[]` (top 5).
- Produces: `factorDetail(days, id): { factor, withDays: SavedDay[], withoutDays: SavedDay[], withAvg, withoutAvg, alsoTrue: string[], worthTrying: string } | null`.
  - `alsoTrue`: up to 2 lines for other fixed factors whose rate differs by 30+ points between the groups, e.g. "You also worked out on 82% of these days vs 20% of the others."
  - `worthTrying`: one template per family and sign. Example (positive workout): "Try fitting in even a short workout on a day that looks quiet, and see if the score follows."
- Produces: `headline(days, prevDays): { avg: number | null; verdict: string; great: number; rough: number; count: number; change: number | null }`.
  - Verdicts: ≥8 "A great stretch", ≥6.5 "A good month with some rough patches", ≥5 "Up and down", otherwise "A tough stretch". The wording says "stretch" rather than "month" when the period isn't a month.
  - great = score ≥ 8; rough = score ≤ 4. `change` is null when prevDays is empty.
- Produces: `highlights(days): { best?: SavedDay; toughest?: SavedDay; bestWeek?: { start: string; end: string; avg: number }; longestStreak: number }`. bestWeek is the 7-day window with 4+ days and the highest average.
- Produces: `peopleScores(days): { name: string; days: number; avg: number }[]` (2+ days, case merged, sorted by avg desc).
- Produces: `series(days, metric: Metric): { date: string; value: number; avg7: number }[]` (avg7 = trailing 7-entry average).

### Task 2: Insights page

- `/insights?period=&month=`:
  - Period chips; month arrows when period=month.
  - Under 14 saved total: the waiting card.
  - Otherwise:
    - Headline card (ring + verdict + "{count} debriefs · {great} great · {rough} rough · ▲/▼ change vs last period").
    - "Your recipe for a good day" list (each row links to its factor page), the honesty line.
    - Trends card (`TrendChart` client component with chips Score / Sleep / Drinks / Workouts / Productive / Focus).
    - Highlights tiles (each links to its day, or to the Journal month for best week).
    - People list. Ask your AI.
  - Computer (lg): 3 columns. Left: headline + people. Middle: recipe. Right: trends + highlights + Ask your AI.
- `TrendChart({ points })`: an SVG with a dot per day colored by score (score metric) or accent (others) and a sage 7-day line. Each dot links to `/day/{date}`. A label row shows the min, max and average.
